# 升级到 0.2.2（自动注册）

> 日期：2026-09-06 ｜ 摘要：webcore 应用可自动接入导航站/注册中心——配置一行，启动即上架。

## 改动清单

### 新增
- `WebConfig.registry` 配置段 + 注册代理 `attachRegistry`：`server.start()` 成功后自动
  POST 到注册中心（id/name/url/端口/描述/分组/图标）并**心跳续命**（缺省 30s）；
  注册中心 90s 无心跳自动下架（进程崩溃也能清理）；进程退出尽力注销
- 注册中心不在线 = 静默失败（不影响站点自身运行）；支持多注册中心并存（各配置各的 url）
- 导航站侧新增 `POST /api/nav/register` / `POST /api/nav/unregister`（外部注册站点只读展示，
  与 yml 注册表条目共存，**yml 条目优先**：id 冲突时外部注册被忽略）

## 🔴 破坏性改动

**无**。`registry` 缺省未配置（`url` 为空 = 不自动注册），既有项目行为完全不变。

## 需要手动操作的事项

- **无需手动操作**。想自动接入门户的项目，在各自 `web.config.json` 加（可选字段均可省略）：
  ```jsonc
  "registry": {
    "url": "http://127.0.0.1:19090",   // 导航站地址（必填才启用）
    "name": "我的站点",                  // 缺省 theme.siteName
    "desc": "一句话描述",
    "tags": ["prod"], "group": "我的项目", "icon": "🚀",
    "heartbeatSec": 30                   // 心跳间隔（注册中心按 90s 无心跳下架）
  }
  ```
- 站点出现在门户卡片上的标注为「自动注册」；需要**托管启停**的站点仍用 yml 注册表条目。

## 验证

```bash
npm run self-test && npm run self-test-cordis
```
端到端：起导航站 → 起带 registry 配置的应用 → 门户出现该站点（alive 探测真实端口）→
杀应用 → 90s 内自动下架。
