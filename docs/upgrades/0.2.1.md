# 升级到 0.2.1（端口记忆）

> 日期：2026-09-06 ｜ 摘要：稳定端口——实际端口持久化，重启钉住不漂移。

## 改动清单

### 新增
- `server.portMemory`（缺省 **true**）：实际监听端口写入 `state/port.memory.json`
  （按 portKey 分键：常规应用 `default`、共享核站点 = 站点 id）
- 下次启动**优先使用上次实际端口**（不再从首选端口重新探测）——多 web 各自占位后重启不互抢、不换号
- 记忆端口被占 → +1 顺延并**更新记忆**；配置端口变更 → 以新配置为准（记忆自动重建）

## 🔴 破坏性改动

**无 API/配置破坏**。但有一个**行为变化**需要知道：

- **启动端口可能不再等于配置文件里的首选端口**（首次顺延后钉在顺延端口；重启沿用）。
  这是设计意图（稳定端口），如期望"总是用首选端口"，可关闭：
  ```jsonc
  { "server": { "portMemory": false } }
  ```
  或删除 `state/port.memory.json` 重置记忆（下次按首选端口重新探测）。

## 需要手动操作的事项

- **无需手动操作**。想重置某站点端口：删该项目 `state/port.memory.json` 中对应键或整个文件。
- 随机端口（`"port": 0`）不记忆，行为不变。

## 验证

```bash
npm run self-test && npm run self-test-cordis
```
启动后检查 `state/port.memory.json` 内容即实际记忆端口。
