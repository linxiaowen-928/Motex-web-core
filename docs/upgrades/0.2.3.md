# 升级到 0.2.3（控件初始化顺序修复）

> 日期：2026-09-07 ｜ 摘要：修复浏览器端控件（data-motex-*）可能完全失效的根因。

## 改动清单

### 修复（重要）
- **base.js 移到 `<head>` 且先于所有区块 requires 脚本**：defer 脚本按文档顺序执行，
  此前 base.js 在 body 末尾、区块脚本（如门户 nav.js）在 head → 区块脚本先跑时
  `window.MOTEX` 尚不存在，控件从未注册——**页面交互（按钮等）零响应且无任何日志**。
  现在任何项目自写控件脚本都能正确注册。

## 🔴 破坏性改动

**无**。仅脚本标签位置变化（defer 语义不变，执行顺序更合理）；若个别页面曾依赖
"base.js 在 body 底部"（如直接读其后的 DOM）——defer 本就保证 DOMContentLoaded 前执行，
不受影响。

## 需要手动操作的事项

- 示例站 `features` 区块不再重复声明 `requires: ['base.js']`（布局统一引入）——
  其他项目若有同样声明可移除（留着也无害，仅重复加载同一 URL）。
- 建议项目控件脚本参照门户 nav.js 写防御式初始化（等 `window.MOTEX` 就绪 + 注册后自行点亮）。

## 验证

```bash
npm run self-test && npm run self-test-cordis
```
页面源码检查：`<head>` 中 `/assets/base.js` 必须出现在所有区块脚本（如 nav.js）之前。
